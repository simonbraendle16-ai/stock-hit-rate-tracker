# Automatic trade analysis, 2026-10-17

User requirement: Every newly saved or corrected trade must automatically appear in each applicable analysis, permanently, without a manual research opt-in or a duplicated wave record. Existing main-push authorization applies.

The read model already included every owned trade, but only displayed field coverage under a misleading linked-trade introduction. TrackingPage additionally discarded loaded trade samples and coverage when rendering FibonacciPanel. Saves invalidated other routes but omitted /analysis. The new shared summary groups status and direction, computes current planned CRV, and reports known qualitative outcomes with its own explicitly defined denominator. Financial results remain separate, strictly based on actual evidence and money/demo classification. Empty plan objects do not count as confirmed plan information.

Both /analysis and /tracking render the shared summary. Tracking's primary trade summary respects the selected portfolio; the wave research's independent trade sample remains explicitly defined by instrument only. Tracking passes the complete research props instead of silently discarding trade data. Successful UI/API creation, metadata/plan changes, position changes and settlement updates invalidate the analysis routes. API retry remains idempotent. Open pages refresh upon visible return and every visible minute; hidden/unmounted pages do not poll. Refresh invokes existing read paths only, does not place trades or add a service. There is no new data migration or production personal-data write.

Validation: Final full suite 98 files / 1427 tests passed; targeted 5 files / 40 tests passed, including real isolated PostgreSQL creation through UI actions and API handlers, next-read inclusion, metadata PATCH and unchanged retry. Separate typecheck and final production build passed. Refresh's visible/hidden/focus/cleanup behavior tested with fake timers. Actual browser saved synthetic local FIBQA-S trade #1 and immediately read count=1, direction=long, wave=C, planned CRV=5 and qualitative note, with no actual execution or settlement. Initial fixture currencies were populated only in loopback PostgreSQL. No technical test data in production.

Final production deployment and read-only UI/API evidence are recorded in the Trading-Assistent project report Trade-Auswertung-Dauerhaft-2026-10-17.md after publication. This local document does not itself claim a production release.
