User request 2026-10-22: reduce recurring Neon transfer to fit the existing free allowance; the unused trainer can be disabled. No data deletion, paid resources, reduced demo/alarm cadence or automatic publication.

Implemented on top of prepared manifest revision commit `f467846`:

Both server-action modules reject at their common identity guard before auth/database work. Requests containing `trainingSessionId` receive HTTP 410 before auth/DB/provider access. Navigation and the rated-exercise link are hidden; ordinary charts and their local replay remain available. Existing training tables and rows are untouched. Re-enable only via a deliberate code/deployment change.

- `market-data/candle-store.ts` skips the series query altogether for stored-only reads. Ordinary freshness checks select only `fetchedAt`. Candle SQL limits, ordering and provider freshness/failure behavior remain intact.
- Watchlist sparklines previously fetched up to 300 full daily OHLCV candles and then sliced 90 close values. The fresh-store path now selects only 90 closes in SQL; stale/empty series still use the established provider/merge/failure path with a bounded 90-row delivery. Duplicate confirmed symbol/market pairs share one promise per request, never a cross-request cache. Quote-only requests and visible refresh cadence are unchanged.
