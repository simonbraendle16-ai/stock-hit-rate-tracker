# Tracker design completion · 2026-11-01

## Behavior

- Desktop navigation retains its 180px width at 16px from the viewport edge. Wide workspaces use the remaining width. Tablet and mobile navigation and narrower forms retain their existing responsive rules.
- Cockpit shows separate owned observation, instrument, forecast-assessment and current-depot trade counts. No common profit or hit-rate is computed across those populations. Counts are aggregate SQL queries, not downloaded observation payloads.
- Collection has its own authenticated route at /collection?fib.basis=1, using the existing Fibonacci form, revision and readback contract. Its context link opens the same selection in /analysis. No second store, automatic classification or migration.
- /forecasts exposes the existing forecast statistics and links to instrument-level assessments. Existing /analysis, /tracking and instrument links remain available.
- Panorama, Statistikstudio and Strukturvergleich remain three tabs of the same population. The existing switcher precedes the long filters. Time and duration aggregates from S7 are integrated without additional network reads.
- Loading and data-error states retain the common navigation. API settings use the same frame. Instrument details and broker orders activate their parent workspace. Trainer stays disabled.

## Using the interface

Open Wellenstatistik, search and confirm criteria, select one of the three perspectives, then optionally open Datengrundlage to inspect cases or export CSV. Details preserve the selection and return context. Use Datensammlung to record/correct observations; use its context link to continue with that selection in the statistics. Prognoseprüfung and depot-based trade results have separate populations.

## Validation and release

Run TypeScript separately: the existing Next build configuration skips type validation. Run Vitest with bounded workers, without a simultaneous production build. Use a local synthetic PGlite preview for UI writes and independent database readback; never create production test observations. Validate desktop widths 1440/1920, tablet 1024, mobile 390, all three perspectives, navigation, collection create/correct and version increments.

No public API/schema or trading-rule change. Production release requires the authorized main push, successful deployment status, read-only UI/API checks and comparison with the pre-release observation fingerprint. A personal Voice/Broker test is outside this design release. Rollback is a revert of the design commit after checking subsequent work; no database rollback is required.

Tab activation is deliberate (click or Enter), not a side effect of restored focus. The location hook keeps the latest pending selection for consecutive focus/click events and skips stale URL-persistence effects. Browser regression covers focus without activation, Enter, rapid switching, reload and detail return.
